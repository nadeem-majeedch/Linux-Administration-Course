## 3. Constraints and how they shape the build

1. **No rewrites of approved content** — teaching package *references* modules; it never re-teaches them in full. Where a lab already exists, the workbook indexes it instead of cloning it.
2. **Public/private separation** — the repo (and GitHub Pages) is public. Instructor-only files live under `teaching/instructor-resources/` and `teaching/assessments/**/keys-*/`; they get **no mkdocs nav entries**, and student-facing pages link to them only with an explicit instructor note. `INSTRUCTOR-ONLY.md` documents why Pages can't enforce access and recommends private distribution (LMS, separate private repo, direct distribution).
3. **No fabricated facts** — every command/output in decks, demos, and keys must be drawn from existing validated module content or be verifiable Ubuntu behavior; risky commands carry Purpose/Risk/Safe-environment/Recovery blocks.
4. **CLO status** — always "proposed, pending instructor review" (per `accreditation/`).
5. **CI assertions stay honest** — if the strict build flags new files, fix content/links, never the assertions.

## 5. Design decisions (recorded to prevent drift)

- **8 unit-level decks instead of 32 module decks.** The roadmap's units are the natural lecture granularity (2 sessions/week × 16 weeks ≈ one unit per 2 weeks). Unit decks keep every module's content as named slide sections with module anchors; this keeps slide count teachable (~60–80 slides/deck) and avoids 32 thin files. The decks index maps each module → its slide section.
- **Assignments 4–6 are new topics**, deliberately not overlapping A1 (organization), A2 (pipeline), A3 (remote operator): A4 shell automation/CLI hardening, A5 networking+services diagnosis, A6 DS-server hardening & incident report.
- **Quiz bank v2 adds formats** (MCQ, command-interpretation, output-reading) that the scenario-only v1 bank intentionally lacks — gaps, not replacements; v1 bank remains canonical for scenario items.
- **Viva student-prep vs protected viva:** the capstone viva bank (29 Q, instructor) stays put; `revision/viva-questions.md` is a *general* self-test bank so students can practice oral defense without leaking the protected bank.
- **Cheatsheets are indexed, never copied.**

## 7. Risks & assumptions

| Risk | Mitigation |
|---|---|
| Public Pages exposes instructor keys | keys get zero nav entries; INSTRUCTOR-ONLY.md documents LMS/private-repo distribution; student files reference keys only as "held by your instructor" |
| Decks drift from module content | every deck section cites its module path; slides are summaries + teaching moves, never re-lessons |
| 16-week plan vs 30-module volume | mapping doc states the compression policy explicitly (2 modules/week default, companion modules folded into capstone weeks, M15 inside Week 9's env block) |
| Fabricated output in keys/decks | all expected outputs copied from validated module pages or marked "output varies"; no invented numbers |
| Build/CI breaks | strict build + full link battery before/after nav change; CI assertions untouched |
| Session count mismatch (32 sessions vs plan) | plan uses 32 sessions with 2 float/revision slots identified in the mapping doc |
