# Cheatsheets

One printable page per unit, plus two special cards. Print them, tape them to the
monitor edge, and retire them one by one as commands move into muscle memory.

> For **per-topic** command references (20 sheets: processes, storage, docker,
> troubleshooting, …) see the course-level [`cheatsheets/`](../../cheatsheets/README.md)
> directory — these unit cards stay broader and lighter.

| Sheet | Covers | Modules |
|---|---|---|
| [unit1-foundations.md](unit1-foundations.md) | System identification, distro families, architecture layers, VMs | M01–M04 |
| [unit2-command-line.md](unit2-command-line.md) | Navigation, file ops, text tools, pipes | M05–M09 |
| [unit3-scripting.md](unit3-scripting.md) | Bash structure, strict mode, traps, getopts | M10–M11 |
| [unit4-admin.md](unit4-admin.md) | Permissions, ownership, ACLs, sudo, environment | M12–M15 |
| [unit5-software-storage-time.md](unit5-software-storage-time.md) | apt, disks/mounting, processes/signals, cron | M16–M19 |
| [unit6-services-networking.md](unit6-services-networking.md) | systemctl, network diagnosis, SSH, rsync, journalctl, ufw | M20–M25 |
| [unit7-data-science-stack.md](unit7-data-science-stack.md) | Git, venv/Jupyter, Docker, nginx/Postgres deploy | M26–M29 |
| [capstone-ops.md](capstone-ops.md) | The operations runbook card: daily commands for your deployed system | M30 |
| [safety-card.md](safety-card.md) | The watchlist of dangerous commands and their safeguards — read before every lab | all |

Maintenance rule: a cheatsheet may only contain commands that a module's lab actually
uses. If a command has no home module, it doesn't belong on the card.
