# datasets/

Small, course-owned datasets used by labs, exercises, mini-projects, and the capstone.

## Naming and layout

Each dataset lives in its own subdirectory with a `README.md` documenting provenance,
schema, and *known quirks* (intentional dirtiness is part of the pedagogy; undeclared
dirtiness is a bug):

```
datasets/
├── README.md                  ← this file
├── sales-2019-q1.csv          (or sales-2019-q1/sales-2019-q1.csv + README)
├── server.log
├── access.log
├── syslog-sample.log
├── students.csv
├── sensor-telemetry.tsv
└── expected/                  ← known-good outputs for self-checking
```

> **.gitignore note:** bulk `*.csv`/`*.tsv`/`*.zip` files are ignored by the root
> `.gitignore` so that large generated files never enter Git. Files under
> `datasets/expected/` are exempted. Datasets committed here must be small
> (guideline: ≤ ~10 MB; most are a few KB); anything larger ships as a
> generation script or an external link with checksums (see CONTRIBUTING.md).

## Generation and verification

- Datasets are generated by reviewed scripts where possible (see CONTRIBUTING.md,
  "Dataset Contributions") so they are reproducible and license-clean.
- `sha256sum` values for each file are published in the dataset's own README and in
  `expected/` — students verify integrity in M02/M23 as a practiced habit.
- All data is **fictional and synthetic**. No real personal data is used anywhere in
  the course. If an external public dataset is ever adopted, it carries its own
  documented license and provenance statement per CONTRIBUTING.md.

## Adding a dataset

Open an issue first (see CONTRIBUTING.md). A dataset PR must include: the data files
(or generator script), a dataset README (schema, provenance, license, known quirks),
checksums, and at least one exercise that uses it.
